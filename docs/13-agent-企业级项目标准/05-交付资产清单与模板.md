# 05. 交付资产清单与模板

## 1. 先说结论：企业级项目交付的不是一段 Agent 逻辑，而是一组可维护资产

一个企业级 Agent 项目交付时，至少应该同时交付：

- 文档
- 接口
- 配置
- 测试
- 安全证据
- 评估报告
- 运维手册
- 变更和责任机制

否则后续很容易变成“只有开发者本人知道怎么跑”的项目。

## 2. 交付资产清单

| 类别 | 必备资产 |
| --- | --- |
| 项目入口 | README、快速开始、架构图、目录说明 |
| 产品定义 | 场景说明、用户角色、输入输出、不适用场景 |
| 架构设计 | 数据流、控制流、权限流、状态机、模块边界 |
| API | OpenAPI/protobuf、错误码、鉴权方式、幂等字段 |
| 配置 | 配置 schema、环境变量、默认值、安全配置说明 |
| 安全 | 威胁模型、权限矩阵、红队样本、审计字段 |
| 评估 | 评估集、评估脚本、上线报告、回归记录 |
| 运维 | SLO、告警、Runbook、回滚流程、事故复盘模板 |
| 工程 | 单元测试、集成测试、CI、部署说明、Docker Compose |
| 治理 | ADR、RACI、风险登记册、变更记录 |

## 4. RACI 模板

| 工作项 | Responsible | Accountable | Consulted | Informed |
| --- | --- | --- | --- | --- |
| 模型版本变更 | AI 应用工程师 | 技术负责人 | 安全、业务 | 运维 |
| 工具权限变更 | 后端工程师 | 安全负责人 | 业务负责人 | 运维 |
| 高风险动作放量 | 业务负责人 | 产品负责人 | 安全、法务 | 客服 |
| 事故回滚 | 值班工程师 | 技术负责人 | 安全、业务 | 相关团队 |
