# 00. 企业级项目总览

## 1. 先说结论：企业级 Agent 项目不是“效果不错”，而是“边界清楚、结果可验、风险可控、运行可管”

一个 Agent Demo 可以只证明一件事：

- 模型、工具和 Prompt 的组合在某些输入下能跑通。

但企业级项目必须证明更多事情：

- 它服务哪个业务目标
- 它不能做什么
- 它失败时代价是什么
- 它调用工具时是否被权限约束
- 它的结果能不能被验证
- 它上线后谁运营、谁接警、谁回滚

所以企业级 Agent 的标准不是“看起来聪明”，而是：

> 能在明确边界内稳定完成任务，并且每次关键行为都能被追踪、解释和治理。

## 2. 成熟度分级

| 等级 | 状态 | 典型特征 | 不适合做什么 |
| --- | --- | --- | --- |
| L0 | 概念验证 | 手动运行、少量样例、无稳定接口 | 不适合接真实用户 |
| L1 | MVP | 有 API、有少量评估样本、有基础日志 | 不适合自动执行高风险动作 |
| L2 | 试点上线 | 有权限、审计、回归评估、人工确认 | 不适合大规模平台复用 |
| L3 | 生产可运营 | 有 SLO、Runbook、监控、回滚、成本治理 | 可服务明确业务场景 |
| L4 | 平台化能力 | 多租户、多场景、统一策略、持续评估 | 可作为企业 AI 应用底座 |

企业项目至少应该达到 L3，才算真正进入生产级。

## 3. 企业级项目必须明确的 7 个边界

1. **业务边界**  
   它解决哪类任务，不解决哪类任务。

2. **用户边界**  
   谁能使用，谁能审批，谁能接管。

3. **数据边界**  
   能读取哪些数据源，哪些数据必须脱敏，哪些数据不能进入模型上下文。

4. **工具边界**  
   哪些工具只读，哪些低风险写，哪些高风险动作必须人工确认。

5. **自动化边界**  
   哪些步骤允许自动执行，哪些只能生成草稿或 dry-run。

6. **质量边界**  
   什么叫成功，什么叫关键错误，什么情况必须拒答或转人工。

7. **运维边界**  
   谁负责配置、发布、告警、回滚、复盘和成本控制。

## 4. 最小上线准入

一个 Agent 项目上线前，至少要通过下面检查：

| 类别 | 准入要求 |
| --- | --- |
| 场景 | 有明确目标、用户、输入输出和失败代价 |
| 权限 | 读写权限分层，高风险动作有审批或确认 |
| 评估 | 至少有主路径、边界样本、高风险样本 |
| 日志 | 能追踪输入、上下文、工具调用、模型版本、输出 |
| 安全 | 有提示注入、越权访问、敏感信息泄露的测试样本 |
| 运维 | 有 SLO、告警、Runbook、回滚流程 |
| 工程 | API 契约、配置、测试、部署说明齐全 |

## 5. 推荐推进顺序

1. 先定义业务场景和失败代价。
2. 再画出数据流、工具流和权限流。
3. 然后实现最小闭环和评估集。
4. 接着补审计、监控、人工确认和回滚。
5. 最后扩大自动化范围和平台复用范围。

不要反过来做：

- 先给 Agent 很多工具
- 再等线上出问题后补权限
- 最后才想怎么评估

这会让系统越强越危险，也越难治理。

## 6. 企业级交付的核心判断

企业级 Agent 项目必须回答一句话：

> 如果它今天做错了，团队能不能知道错在哪里、影响了谁、怎么停下、怎么修复、怎么避免再发生。

如果答案是否定的，它还不是企业级项目。
