# 02. 接口与配置清单

## 1. 先说结论：企业级 RAG 项目最容易缺的不是代码，而是接口约定和配置清单

很多项目能跑通，  
但一换环境、一加数据源、一做回滚就出问题，  
通常是因为：

- 关键配置没有统一管理
- 版本号没有制度化
- 接口字段没有定清楚
- 上线检查表缺失

所以这一篇整理的是 **最少应该固化下来的接口和配置**。

## 2. 关键接口建议

### 2.1 Ingestion

```go
type SourceConnector interface {
    PullChanges(ctx context.Context, cursor string) ([]SourceRecord, string, error)
}
```

关键字段：

- `cursor`
- `source_system`
- `object_id`
- `updated_at`
- `deleted`
- `acl`

### 2.2 Retrieval

```go
type Retriever interface {
    Retrieve(ctx context.Context, query QueryContext) ([]Candidate, error)
}
```

关键字段：

- `tenant_id`
- `user_id`
- `roles`
- `scene`
- `max_results`

### 2.3 Generation

```go
type Generator interface {
    Generate(ctx context.Context, req GenerationRequest) (GenerationResult, error)
}
```

关键字段：

- `prompt_version`
- `model`
- `citations`
- `need_agent`

### 2.4 Orchestration

```go
type Orchestrator interface {
    Run(ctx context.Context, task AgentTask) (TaskResult, error)
}
```

关键字段：

- `task_id`
- `tool_permissions`
- `approval_policy`
- `trace_id`

## 3. 关键配置项建议

### 3.1 检索配置

- `retrieval.mode`
- `retrieval.top_k`
- `retrieval.rerank.enabled`
- `retrieval.timeout_ms`

### 3.2 向量配置

- `embedding.model`
- `embedding.dimension`
- `embedding.batch_size`
- `embedding.timeout_ms`

### 3.3 RedisSearch 配置

- `redisearch.index_alias`
- `redisearch.ef_runtime`
- `redisearch.knn_k`
- `redisearch.pipeline_batch_size`

### 3.4 治理配置

- `dataset.version`
- `prompt.version`
- `acl.enforcement_mode`
- `rebuild.shadow_read_ratio`

## 4. 上线前检查表

1. 数据源 cursor 和增量同步是否可验证
2. 删除事件是否能传播
3. ACL 是否进入索引
4. 是否能返回引用来源
5. 是否能记录 `dataset_version` 和 `index_version`
6. 是否有重建和回滚流程
7. 是否有查询日志和 trace
8. 是否有基本评估集

## 5. 小结

- 明确接口和配置清单，本质上是在降低后续扩展和运维成本
- 这些清单越早固定，后面接入新业务和新数据源越轻松
