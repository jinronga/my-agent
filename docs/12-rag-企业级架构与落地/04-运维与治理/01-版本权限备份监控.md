# 01. 版本、权限、备份与监控

## 1. 先说结论：没有治理能力的 RAG，很难在企业里长期存活

很多 RAG 系统在演示阶段看起来已经能用了：

- 能回答问题
- 能给出引用
- 能接几个数据源

但一进入企业环境，  
真正决定能不能长期运行的，往往不是首屏效果，  
而是这些问题：

- 新旧索引怎么切？
- 权限怎么前置？
- 数据丢了怎么恢复？
- 检索变慢了怎么发现？
- 回答质量掉了怎么定位？

所以本篇的核心判断是：

**版本、权限、备份、监控不是上线后的附加项，而是企业级 RAG 的基础能力。**

## 2. 版本至少要分三层

### 2.1 数据集版本

表示同一批源数据的逻辑快照。  
例如：

- `dataset_version=2026-04-12T01`

主要用于：

- 标记这批数据来自哪次同步
- 对账和追溯

### 2.2 索引版本

表示索引构建产物版本。  
例如：

- `index_version=idx-rag-prod-20260412-01`

主要用于：

- 切换线上 alias
- 灰度和回滚

### 2.3 prompt / generation 版本

表示生成层模板、模型、引用格式、输出协议版本。

如果不把这个单独记录，  
后面很难区分：

- 是检索错了
- 还是生成策略变了

## 3. 权限隔离建议

### 3.1 权限必须尽量前置到检索阶段

不建议只在答案返回前做“结果删减”。  
更稳的做法是：

- 检索阶段先做租户 / 角色 / 用户过滤
- 生成阶段再做一次最终校验

### 3.2 权限层级建议

至少考虑：

- 租户级
- 部门 / 组织级
- 角色级
- 用户级
- 文档级保密标签

### 3.3 权限数据建模建议

可以保留：

- `tenant_id`
- `org_path`
- `acl_roles`
- `acl_users`
- `sensitivity_level`
- `acl_fingerprint`

其中 `acl_fingerprint` 的作用很重要：  
它能帮助判断“这条索引记录使用的是哪一版权限投影结果”。

## 4. 备份与恢复要怎么想

### 4.1 不要把 RedisSearch 当成唯一事实来源

更稳的做法是：

- 原始数据保留在源系统或对象存储
- 解析结果保留在对象存储
- 索引可重建

也就是说：

**索引应该被设计成可再生资产，而不是唯一真相。**

### 4.2 推荐的备份对象

1. 元数据数据库  
保存 cursor、版本、任务状态、索引映射关系。

2. 原始文档与解析产物  
支持重建和审计。

3. 检索配置  
包括字段映射、权重、查询模板、索引参数。

4. 评估集和查询日志  
支持恢复后回放验证。

### 4.3 恢复策略

至少准备两套恢复路径：

- **快速恢复**：恢复最近快照和 alias
- **完全重建**：从原始数据和配置重新建索引

## 5. 监控至少覆盖四类指标

### 5.1 数据新鲜度

- 数据源同步延迟
- embedding 队列积压
- 索引发布时间
- 最新文档可检索延迟

### 5.2 在线检索性能

- 检索 p50 / p95 / p99
- rerank 耗时
- 生成耗时
- 端到端耗时

### 5.3 结果质量

- 无命中率
- 引用缺失率
- 低置信度回答比例
- 用户追问率

### 5.4 安全与权限

- 权限拦截次数
- 越权告警数
- 高敏内容检索次数
- 人工接管率

## 6. 推荐的告警规则

1. **数据新鲜度告警**  
当文档更新超过 SLA 仍未入索引。

2. **检索延迟告警**  
当 `p95` 超过阈值持续一段时间。

3. **无结果率异常告警**  
可能意味着索引或查询模板出了问题。

4. **引用缺失告警**  
可能意味着生成层配置回退或上下文打包异常。

5. **权限异常告警**  
任何越权命中都应该高度关注。

## 7. 监控系统建议

在 Go 技术栈下，  
推荐至少接入：

- Prometheus：指标采集
- Grafana：大盘
- OpenTelemetry：trace
- 统一日志平台：请求日志和任务日志

关键 trace span 建议包括：

- `query.parse`
- `retrieval.search`
- `retrieval.rerank`
- `generation.call`
- `orchestrator.tool`
- `ingestion.embed`
- `index.publish`

## 8. 审计日志建议

建议每次请求至少记录：

- 请求 ID
- 用户身份
- 查询文本或任务摘要
- 命中的 chunk / 文档 ID
- 使用的 `dataset_version`
- 使用的 `index_version`
- 使用的 prompt 版本
- 是否调用工具
- 是否触发人工确认

## 9. 小结

- 版本要至少分成数据集、索引和生成三层
- 权限要前置到检索，不要只做答案后处理
- 索引必须被设计成可重建资产
- 监控不仅要看延迟，还要看新鲜度、质量和权限异常
